# Architecture Decisions

## ADR-001: 三层知识检索架构
- 日期: 2026-06-01
- 背景: 知识库需要同时支持精确搜索和语义理解
- 选项: A) 仅全文搜索 / B) 仅向量搜索 / C) 分层检索
- 决定: C — 三层检索
- 原因: 不同场景需要不同检索策略，分层可以兼顾速度和智能
- 影响:
  - 第一层 FTS5：精确关键词匹配，速度最快，SQLite 内置
  - 第二层 ChromaDB：向量语义检索，模糊/关联匹配
  - 第三层 RAG：检索 + LLM 综合回答，最智能但最慢
  - 检索策略：简单查询只走第一层，复杂查询逐层升级

## ADR-002: 执行器无隔离设计
- 日期: 2026-06-01
- 背景: 需要决定命令执行是否使用容器/沙箱隔离
- 选项: A) Docker 沙箱 / B) 子进程受限执行 / C) 直接 Shell 执行
- 决定: C — 直接 Shell 执行
- 原因: 个人助手场景，用户信任度高；隔离会增加延迟和复杂度；全盘文件访问是核心需求
- 影响:
  - 需要完善的安全分级策略（安全/新指令/危险三级）
  - 不适合多租户场景（但 Friday 不需要）
  - 首次执行新命令需用户确认，确认后自动加入白名单

## ADR-003: 双层记忆架构
- 日期: 2026-06-01
- 背景: AI 助手需要记住用户偏好和项目知识，同时需要 Git 可管理
- 选项: A) 纯向量记忆 / B) 纯文件记忆 / C) 双层混合
- 决定: C — Mem0 动态记忆 + 结构化文件记忆
- 原因: 动态记忆适合自动提取偏好/习惯，文件记忆适合团队协作和 Git 版本管理
- 影响:
  - Mem0 按 project_id 分区，存 ChromaDB
  - 文件记忆放在 .specify/memory/ 下，跟代码一起 Git 管理
  - LLM 的 System Prompt 需要同时注入两种记忆

## ADR-004: 指令学习的 YAML 格式
- 日期: 2026-06-01
- 背景: 用户教给 Friday 的操作需要持久化存储
- 决定: YAML 格式存储在 ~/.friday/instructions/
- 原因: 人可读、易编辑、支持复杂结构（多步工作流、条件分支）
- 影响:
  - 单步指令：trigger + action 格式
  - 多步工作流：有序步骤链，支持变量传递
  - 条件分支：if-else 逻辑
  - 对话式教学自动生成 YAML，用户也可以直接编辑

## ADR-005: LLM 调用层 Adapter 模式
- 日期: 2026-06-01
- 背景: 需要支持多个 LLM 提供商，随时切换
- 决定: adapter 模式，统一接口，配置切换
- 原因: 不同模型有不同优势（智谱中文强，DeepSeek 代码强），按需切换
- 影响:
  - 统一的 prompt 组装：项目记忆 + 动态记忆 + 指令列表 + 知识上下文
  - 统一的工具调用接口：Shell/文件/知识库
  - config.yaml 中配置默认模型和备选模型
