# Feature Specification: 执行器模块

**Feature Branch**: `004-executor`

**Created**: 2026-06-02

**Status**: Draft

**Input**: User description: "执行器模块"

## User Scenarios & Testing

### User Story 1 - 基础命令执行 (Priority: P1)

用户对 Friday 说"帮我查看当前目录下的文件"，Friday 识别意图后通过执行器运行 Shell 命令，将结果展示给用户。安全命令（如 ls、cat、pwd）直接执行，无需额外确认。

**Why this priority**: 命令执行是 Friday 的核心能力，没有它 Friday 无法替用户做事。安全命令的自动执行是最基础的场景。

**Independent Test**: 可以通过发送一条安全命令（如"列出当前目录文件"）并验证结果来独立测试。

**Acceptance Scenarios**:

1. **Given** 用户在交互模式中，**When** 用户说"列出当前目录的文件"，**Then** Friday 执行对应命令并将结果直接展示给用户
2. **Given** 命令属于安全类别，**When** 执行器收到该命令，**Then** 命令自动执行，不弹出确认提示
3. **Given** 命令执行成功，**When** 输出内容少于 20 行，**Then** 完整展示原始输出
4. **Given** 命令执行成功，**When** 输出内容超过 20 行，**Then** 对输出进行智能摘要后展示

---

### User Story 2 - 分级安全确认 (Priority: P2)

用户让 Friday 执行一个未归类或潜在风险的命令（如删除文件、安装软件包），Friday 根据安全等级要求用户确认后才能执行。用户可以记住对某个命令的信任选择，下次无需再确认。

**Why this priority**: 安全是执行器的关键设计。没有分级确认，用户不敢让 Friday 执行有风险的命令。

**Independent Test**: 发送一条危险命令（如 rm），验证确认提示出现；确认后验证命令执行。

**Acceptance Scenarios**:

1. **Given** 命令属于"新指令"类别（首次遇到），**When** 执行器收到该命令，**Then** 弹出一次性确认提示，用户确认后执行并记住该命令
2. **Given** 命令属于"危险"类别（如 rm、rmdir、sudo），**When** 执行器收到该命令，**Then** 每次都弹出确认提示，即使之前确认过
3. **Given** 用户在确认时选择"以后都信任此命令"，**When** 该命令再次出现且不是危险命令，**Then** 自动执行不弹确认
4. **Given** 用户在确认时选择"拒绝"，**When** 执行器收到该命令，**Then** 不执行并告知用户

---

### User Story 3 - 命令超时与异常处理 (Priority: P3)

用户让 Friday 执行一个长时间运行的命令或一个不存在的命令，Friday 能够优雅地处理超时和错误，并将友好的错误信息展示给用户。

**Why this priority**: 异常处理保证执行器在非正常情况下的可靠性，是生产可用的必要条件。

**Independent Test**: 发送一条不存在的命令或设置短超时，验证错误信息友好展示。

**Acceptance Scenarios**:

1. **Given** 命令执行超过 30 秒，**When** 执行器检测到超时，**Then** 终止命令并提示用户"命令执行超时"
2. **Given** 命令不存在（如拼写错误），**When** 执行器收到该命令，**Then** 展示友好的错误信息，包含系统原始错误
3. **Given** 命令返回非零退出码，**When** 执行器收到结果，**Then** 标记为执行失败并展示错误输出
4. **Given** 命令被用户中断（Ctrl+C），**When** 执行器检测到中断信号，**Then** 清理子进程并恢复交互状态

---

### User Story 4 - 命令历史与日志 (Priority: P4)

Friday 自动记录每次命令执行的历史，包括命令内容、执行时间、结果状态。用户可以查看最近的执行历史。

**Why this priority**: 历史记录帮助用户回顾操作，也便于调试问题。属于增值功能。

**Independent Test**: 执行几条命令后，查看执行历史，验证记录完整。

**Acceptance Scenarios**:

1. **Given** 任意命令被执行，**When** 执行完成（无论成功失败），**Then** 自动记录到执行历史
2. **Given** 用户查看执行历史，**When** 请求最近 N 条记录，**Then** 展示包含命令、时间、状态的列表
3. **Given** 历史记录超过存储上限，**When** 写入新记录，**Then** 自动清理最旧的记录

---

### Edge Cases

- 命令输出包含二进制数据（如图片文件）时如何处理？→ MVP 阶段忽略二进制内容，只展示文本输出
- 命令需要交互式输入（如 sudo 密码）时如何处理？→ MVP 不支持，提示用户该命令需要交互输入
- 并发执行多条命令时如何管理？→ MVP 串行执行，不支持并发
- 命令执行过程中系统资源不足时如何处理？→ 依赖系统本身的资源管理，执行器不做额外处理

## Requirements

### Functional Requirements

- **FR-001**: 系统必须能执行任意 Shell 命令并捕获标准输出和标准错误
- **FR-002**: 系统必须支持三级安全策略：安全（自动执行）、新指令（首次确认）、危险（每次确认）
- **FR-003**: 系统必须维护一个安全命令白名单，白名单内的命令自动执行
- **FR-004**: 系统必须维护一个危险命令黑名单，黑名单内的命令每次都需要确认
- **FR-005**: 用户必须能够对非危险命令标记为"信任"，后续自动执行
- **FR-006**: 系统必须在命令执行超时时自动终止并通知用户
- **FR-007**: 系统必须对长输出（超过阈值）进行智能摘要
- **FR-008**: 系统必须记录每次命令执行的历史（命令、时间、退出码、输出摘要）
- **FR-009**: 系统必须在执行失败时展示友好的错误信息
- **FR-010**: 系统必须支持通过配置文件自定义安全等级和超时时间
- **FR-011**: 命令执行必须在工作目录（用户当前项目目录）下运行
- **FR-012**: 系统必须支持实时流式输出（命令执行过程中逐步展示结果）

### Key Entities

- **执行记录**: 每次命令执行的完整记录，包含命令文本、执行时间、耗时、退出码、输出内容、安全等级
- **安全策略**: 命令的安全分类规则，包含命令模式、所属等级（安全/新指令/危险）
- **用户信任**: 用户对特定命令的信任标记，记录命令模式和授权时间

## Success Criteria

### Measurable Outcomes

- **SC-001**: 用户发出一条安全命令后，1 秒内看到执行结果
- **SC-002**: 危险命令 100% 触发确认提示，无一遗漏
- **SC-003**: 超过 20 行的命令输出自动生成摘要，用户能在 5 秒内理解输出要点
- **SC-004**: 命令执行历史 100% 可追溯，记录包含完整的执行上下文
- **SC-005**: 命令执行异常（超时、不存在、权限不足）时，100% 展示用户友好的错误信息

## Assumptions

- 用户在本机使用 Friday，执行器直接运行本地 Shell，不做沙箱隔离
- 默认 Shell 为系统默认（macOS 为 zsh，Linux 为 bash）
- 超时默认值为 30 秒，用户可通过配置调整
- 长输出阈值默认为 20 行
- 安全白名单包含常见无害命令：ls, pwd, cat, head, tail, echo, wc, find, grep, which, date, whoami, uname
- 危险黑名单包含常见风险命令：rm, rmdir, sudo, chmod, chown, mkfs, dd, format, shutdown, reboot
- 依赖已有的 llm/ 适配层进行输出摘要
- 依赖独立的 SQLite 存储执行历史
- MVP 阶段不支持并发执行，命令串行运行
- MVP 阶段不支持交互式命令（需要用户输入的命令）
