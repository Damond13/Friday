# 功能规格：知识库模块

**Feature Branch**: `003-knowledge-base`

**Created**: 2026-06-02

**Status**: Draft

**Input**: 知识库模块 — 存储、索引和检索用户个人知识

## 开源借鉴

| 项目 | 用途 | 角色 |
|------|------|------|
| ChromaDB | 向量存储与语义检索 | 直接依赖 |
| watchdog | 文件系统监控，自动检测变化并触发索引更新 | 直接依赖 |
| SQLite FTS5 | Python 内置全文搜索，关键词精确匹配 | 内置，无需额外安装 |

不引入重型 RAG 框架（如 LightRAG、LlamaIndex），自建轻量三层检索，保持模块简洁可控。

## 用户故事与测试

### 用户故事 1 - 知识录入 (Priority: P1)

用户通过对话说"记一下 xxx"或使用 `/note` 命令，Friday 将内容保存为 Markdown 笔记文件，并自动建立 FTS5 和 ChromaDB 索引。用户也可以直接将文件放入 `~/.friday/knowledge/` 目录，Friday 会自动发现并索引。

**为何是这个优先级**: 录入是知识库的基础，没有内容就无法检索，必须最先实现。

**独立测试**: 可通过 `/note` 命令写入一条笔记，验证文件创建和索引建立。

**验收场景**:

1. **Given** 用户在交互模式中，**When** 输入"记一下 Python 装饰器就是函数包装器"，**Then** Friday 在 `~/.friday/knowledge/notes/` 下创建 Markdown 文件，内容包含用户输入，且 FTS5 和 ChromaDB 索引已更新
2. **Given** 用户在 `~/.friday/knowledge/notes/` 下新增一个 `.md` 文件，**When** Friday 检测到文件变化，**Then** 自动将该文件内容加入索引
3. **Given** 用户使用 `/note` 命令，**When** 输入 `/note 这是我的笔记内容`，**Then** 创建带标题的笔记文件并索引

---

### 用户故事 2 - 知识检索 (Priority: P2)

用户问"我之前说过什么关于 xxx 的？"，Friday 通过三层递进检索返回相关知识。

**为何是这个优先级**: 检索是知识库的核心价值，但依赖录入功能的数据积累。

**独立测试**: 先手动写入几条测试笔记到知识目录，然后用关键词/语义查询验证检索结果。

**验收场景**:

1. **Given** 知识库中有 10 条笔记，**When** 用户搜索包含某个精确关键词的内容，**Then** FTS5 在 100ms 内返回匹配结果，包含来源文件和匹配片段
2. **Given** 知识库中有关于"部署流程"的笔记但没用"上线"这个词，**When** 用户搜索"上线步骤"，**Then** ChromaDB 语义检索能返回相关结果
3. **Given** 知识库中有多条分散的笔记涉及同一主题，**When** 用户提出综合性问题，**Then** RAG 整合多条知识后给出完整回答，并标注信息来源

---

### 用户故事 3 - 目录监控与增量索引 (Priority: P3)

用户在 `~/.friday/knowledge/` 下增删改文件，Friday 自动检测变化并增量更新索引，无需手动操作。

**为何是这个优先级**: 提升使用体验的便利功能，录入和检索已能满足基本需求。

**独立测试**: 在知识目录下新增、修改、删除文件，验证索引自动同步。

**验收场景**:

1. **Given** 目录监控已启动，**When** 用户在知识目录下新增文件，**Then** 5 秒内文件内容进入索引
2. **Given** 文件已在索引中，**When** 用户修改文件内容，**Then** 索引自动更新为新内容
3. **Given** 文件已在索引中，**When** 用户删除文件，**Then** 索引中移除对应条目

---

### 边界情况

- 知识目录下存在非文本文件（图片、二进制）怎么办？→ 跳过，仅索引 `.md` 和 `.txt` 文件
- 文件内容为空或极短怎么办？→ 跳过不索引，不报错
- 同时大量文件变化怎么办？→ 批量处理，避免频繁重建索引
- ChromaDB 嵌入服务不可用怎么办？→ 降级到仅 FTS5 检索，记录警告日志
- 检索无结果怎么办？→ 返回空结果列表，不报错

## 需求

### 功能需求

- **FR-001**: 支持通过对话（"记一下 xxx"）和 `/note` 命令录入知识
- **FR-002**: 知识以 Markdown 文件存储在 `~/.friday/knowledge/notes/`
- **FR-003**: 支持 FTS5 全文索引，关键词精确匹配，响应时间 < 100ms
- **FR-004**: 支持 ChromaDB 向量索引，语义模糊匹配
- **FR-005**: 支持 RAG 问答：检索相关知识片段 + LLM 综合回答
- **FR-006**: 检索结果按相关度排序，返回来源文件路径和内容摘要
- **FR-007**: 支持 `~/.friday/knowledge/` 目录下 `.md` 和 `.txt` 文件的自动发现和索引
- **FR-008**: 文件变化时增量更新索引，不全量重建
- **FR-009**: 支持知识的删除（删除文件时移除索引）
- **FR-010**: 每条知识包含元数据：创建时间、标签、来源文件路径
- **FR-011**: 检索接口统一，上层模块（LLM 层）无需关心底层存储细节
- **FR-012**: ChromaDB 嵌入服务不可用时降级到仅 FTS5 检索
- **FR-013**: 支持 `/search` 命令直接搜索知识库
- **FR-014**: 支持 `/note` 斜杠命令录入知识

### 关键实体

- **Note（笔记）**: 一条知识记录，属性包括标题、内容、标签、创建时间、文件路径
- **IndexEntry（索引条目）**: 关联 Note，包含 FTS5 全文索引内容和 ChromaDB 向量
- **SearchResult（检索结果）**: 检索返回的内容片段、来源文件路径、相关度分数

## 成功标准

### 可衡量结果

- **SC-001**: 用户通过自然语言 5 秒内完成一条知识的录入
- **SC-002**: FTS5 检索 100 条知识时响应 < 100ms
- **SC-003**: 语义检索返回的结果与查询意图相关度 > 80%（人工评估）
- **SC-004**: RAG 回答基于检索到的知识内容，而非 LLM 自身知识（可验证回答中引用了用户笔记的原文）
- **SC-005**: 文件新增后 5 秒内自动进入索引
- **SC-006**: 增量索引不触发全量重建，仅更新变化部分

## 假设

- 用户主要使用中文知识，但需支持中英混合
- ChromaDB 嵌入使用智谱 API 的 embedding 接口（通过 LLM adapter 层调用）
- 知识量级在万条以内，无需考虑大规模性能优化
- MVP 阶段仅支持文本文件（Markdown / 纯文本），不支持图片、PDF
- 仅索引 `~/.friday/knowledge/` 目录下的文件
- 不支持跨用户共享（个人工具）
